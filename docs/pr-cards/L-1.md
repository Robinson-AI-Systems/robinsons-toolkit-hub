## Scope and risk
Only `rtool mcp --local FOLDER[,FOLDER...]` may expose local tools, never hosted Hub or relay.
Read-only files first (PR #126, as-if merged); later independent guarded shell and git slices.
Canonicalize 1–8 owner-selected folders; refuse relative traversal and resolved paths outside roots.
Limit read to regular UTF-8 files ≤4096 bytes; never silently return partial content.
Bound listing and keep local tool schemas compact. No local access in default `rtool mcp`.
Existing standalone servers, passes, permissions, and account context are unchanged.

## First slice: explicitly enabled file tools
Files: packages/cli/src/local-files.js, mcp.js, commands.js, test/local-files.test.js.
`local.file_list`, `local.file_stat`, `local.file_read` accept relative path and indexed approved root.
No server token or remote call; resolve on each request, refuse outside canonical folder, refuse oversize/binary reads.
Tests: opt-in invisibility, usable listing/stat/read, traversal and symlink escape refusal, oversized read, invalid root/duplicates; real CLI stdio smoke without servers.
Proof: targeted Vitest, npm check, npm test and exact-head CI, full diff self-review and required checks.

## Remaining acceptance
- Shell: strict read-only allow-list; nonallowlisted commands require explicit `confirm: true`,
  bounded timeout and stdout/stderr cap, no sudo, no execution outside authorized folders.
- Git: read-only status, diff, log scoped to approved roots; no implicit write/push ability.
- Directory symlink/race security reviewed before any shell is exposed; avoid hosting local handlers.
- Full smoke test via `rtool mcp --local`; default mode still zero local capabilities.
- Update STATUS and work index as the implementation advances; no placeholder or acceptance claim

## Second slice: bounded Git inspection (PR #127, as-if merged)

The local.git_status, local.git_diff and local.git_log tools use fixed read-only
Git arguments without a shell or user-provided flags. Git metadata must be a
real .git directory inside the owner-selected canonical root. Symlinked or
external metadata is refused; execution uses fixed cwd and environment,
disabled external diff and fsmonitor, a six-second deadline, a 4096-byte
output limit, and no optional locks. Actual temporary-repository unit tests
cover correct output, out-of-root metadata rejection, and the output ceiling.
No arbitrary shell command is enabled. L-1 still requires independently
bounded shell execution and confirmation behavior.

## Third slice: confirmed create-only file output (PR #128, as-if merged)

An owner who explicitly enables local roots may ask `local.file_create`
to create a UTF-8 file up to 16 KiB inside an already-existing approved
directory. The caller must supply `confirm: true`; missing approval,
existing destination, directory traversal, outward symlink, unknown grant,
ambiguous separators, Git metadata paths and oversize content refuse.
The newly created file has restrictive permissions and the response contains
only the path, root, and byte count, never its contents. No arbitrary shell,
overwrite, deletion, provider write or hosted file capability is added.
Regression tests use real temporary filesystem operations and an external
symlink fixture. L-1 remains IN_PROGRESS because safely confined general
shell execution and any additional file mutations are separate acceptance.

## Fourth slice: bounded local search (PR #129, pending checks)

Adds literal read-only source search in granted folders. Limits: 200 directories, 500 entries per directory, 400 files, 512 KiB total, 64 KiB per file, 25 matches. Skips symlinks, hidden files, dependency trees and unsupported formats. A truncated result indicates the bounded scan was incomplete. Test real source matches and scope denial. Shell execution remains separate and unimplemented.

## Fifth slice: guarded local updates (PR #130, as-if merged)

Add local.file_hash for bounded 256 KiB ordinary files and local.file_update for explicitly confirmed text replacement up to 16 KiB. A valid expected SHA-256 must match both before and after private staged writing. A cooperative same-file lock refuses concurrent rtool edits; stage bytes are synced, and rename publishes complete contents. Preserve file permission bits and return only path, size and final digest. Refuse symlinks, outside roots, Git metadata paths, missing files, stale expectations and oversize content. External noncooperating writers are not subject to the cooperative lock; do not claim a kernel-atomic compare-and-swap guarantee. Real filesystem regression tests exercise success, stale-write and lock refusal, and unchanged out-of-scope data. L-1 remains IN_PROGRESS until safe general shell acceptance is independently proved.
