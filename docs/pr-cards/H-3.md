## Fifth implementation boundary — grant-checked encrypted RTC result pages (proposed)

## Sixth implementation boundary — resumable RTC discovery and scale (proposed)

Prior discovery searched only three services per call, with
`incomplete: true` and `next: null` even when more authorized providers
existed. Bounded continuation now provides a five-minute HMAC-signed
opaque cursor bound to original query, exact caller, mode/profile and
current authorized service roster. Each page independently selects and
re-resolves at most three active caller grants, preserving partial provider
failure isolation and on-demand schema only. Missing or invalid secret,
expired/tampered cursor, changed caller or revoked/changed roster fail
closed. For small user limits, cursor advances by actual scanned services;
Hub-owned result metadata is returned only on the first page.
HTTP GET search and native fixed seven-tool MCP broker share the same
continuation behavior. Source accepts up to 100 authorized metadata
entries without eager upstream schema fan-out; per-request response
budget is bounded below 8KiB. A query too broad within one upstream
retains explicit incomplete status and may require narrowing to that
specific server. This PR does not promise upstream pagination for one
service's entire catalog.

with 100 advertised tools each (10,000 total at 100), bounded
schema-independent fan-out, measured elapsed latency and RSS deltas;
read/write execution, hosted migrations and real two-service connected
acceptance are separately OPEN. No production deployment or spending.
