A correlation identifies its service, exact connection, tool, status, provider log ID, and time; derive a single nonsecret change row from those real attempts and outcomes, never an unlinked/invented success. Uncertain provider outcomes remain pending/unavailable. Do not double-write or add a second, weaker logging surface.
- `hub_recent_changes` exposes this durable log in fixed, bounded, owner-and-caller-specific native MCP and HTTPS read-only form. A caller may only read its own history; owner can review all their callers via independently password-verified and rate-limited owner control. Pagination must be tamper-resistant, scoped to caller/filter, time limited, and stable under new writes.

No substitute service, no capability guessing, no cross-service fallback, no background provider requests. If unsupported, report separately unavailable, not an invented result. Revoked/expired/reduced callers cannot search past logs; owner controls can still inspect audit truthfully. Missing schema fails closed. Local health/provider acceptance remain separate.
