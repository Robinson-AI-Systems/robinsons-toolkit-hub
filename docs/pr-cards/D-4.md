## D-4b first implementation slice (PR #101, as-if-merged)

The opt-in `node scripts/relay-permission-probe.mjs --issue NUMBER --authorized-relay-test` command checks an already-bound private relay issue, posts only a randomized **non-executable transport diagnostic comment** and deletes it. It proves read/create/delete on that exact issue only when run with the owner's protected token and reports no secret or comment body. Unit tests cover private repo, bound issue, denied write, cleanup failure and refusal without authorization. It is deliberately not an RTC test. It cannot prove the absence of broader token privileges; inspect the fine-grained token's repository/permission settings independently. No real probe has been executed during this PR.

## D-4c signed-ingress preflight (PR #102, as-if-merged)

The opt-in `node scripts/relay-webhook-probe.mjs --authorized-ingress-test` command requires protected `RELAY_WEBHOOK_SECRET`, `RELAY_REPOSITORY`, `RELAY_EXPECTED_INGRESS_ORIGIN` and `RELAY_INGRESS_TEST_URL`. It posts two deliberately ignored edited `issue_comment` JSON payloads to the exact HTTPS `/api/relay/github` route: one correctly HMAC signed, one corrupted. A valid run must receive 202 `ignored` and 401 `invalid_signature`, respectively; outputs contain neutral statuses only, never bypass credentials, origin or payload. The optional Vercel automation bypass query must be protected; preserve SSO deployment protection. No real ingress acceptance is claimed from unit tests; webhook configuration, real service acceptance and three-route revocation proof remain open. No legitimate GitHub issue is modified.

## D-4d origin and issue scope hardening (PR #103, as-if-merged)

Before binding any real destination, hosted relay configuration now restricts fixed RTC origin URLs to public HTTPS hostnames or public IPv4 addresses, default 443, empty credentials/path/query/fragment. It refuses private/loopback/metadata literals and internal DNS suffixes; local fake-service test mode alone permits localhost loopback. Each issue binding must contain exactly numeric actorId and known server with a unique actor/server pair. This does not resolve public hostname DNS rebinding at connection time: use a trusted, fixed custom RTC service domain and monitor its DNS/service ownership. No origin or pass has been applied to production.

## D-4e isolated signed-ingress boundary (PR #104, as-if-merged)

Inert signed edited events now prove webhook ingress even when `RELAY_SERVERS` and `RELAY_BINDINGS` remain absent: valid HMAC yields 202 ignored, bad HMAC yields 401, malformed signed JSON yields 400. The signature guard runs before any DB/GitHub/runtime initialization; only a real signed created issue comment proceeds to the full runtime, immutable binding, actor checks and replay guard. This is explicitly scoped to owner IN-06 and does not activate custom RTC tools or accept D-4. CI uses synthetic keys only. Hosted acceptance and temporary credential revocation are still pending.
