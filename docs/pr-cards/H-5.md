# H-5 — Hub routed-change history and recent changes

**Existing approved Batch H H-5**; dependency H-4 source engineering from merged PRs #189–#206. H-4 genuine hosted/two-provider direct/relay/Sandbox acceptance remains OPEN and does not authorize a live operation. H-5 source engineering is separately eligible, TEST/read_only only.

## Observable outcome and acceptance (approved design, no new subcards)

- Every routed RTC call has a durable attempted/outcome record already written by H-3 in `hub_rtc_read_audit`. A correlation identifies its service, exact connection, tool, status, provider log ID, and time; derive a single nonsecret change row from those real attempts and outcomes, never an unlinked/invented success. Uncertain provider outcomes remain pending/unavailable. Do not double-write or add a second, weaker logging surface.
- `hub_recent_changes` exposes this durable log in fixed, bounded, owner-and-caller-specific native MCP and HTTPS read-only form. A caller may only read its own history; owner can review all their callers via independently password-verified and rate-limited owner control. Pagination must be tamper-resistant, scoped to caller/filter, time limited, and stable under new writes.
- Optional upstream history only for one explicitly selected currently eligible server and an exact independently granted, discovery-verified read-only `<prefix>_recent_changes` operation (if actually advertised). No substitute service, no capability guessing, no cross-service fallback, no background provider requests. If unsupported, report separately unavailable, not an invented result. Use the existing H-3 audited no-retry dispatcher and pinning.
- Compact text plus structured results, bounded URL/forms/SQL/results and owner HTML escaping. No bearer, secret, tool arguments, ciphertext, sensitive provider logs, or auth values in history. Revoked/expired/reduced callers cannot search past logs; owner controls can still inspect audit truthfully. Missing schema fails closed. Local health/provider acceptance remain separate.
- H-5 verification: focused unit, two-independent-service disposable PostgreSQL and native MCP/HTTPS parity, audit correlation before/after call, denied and ambiguous outcomes, stale identity/owner isolation, offset-free cursor renewal/expiry/filters, owner login and HTML escape, upstream refusal/read-only and no retry, exact-head CI/DB/security/review.
- H-5 external acceptance: next checked `main→live` release, deployed schema visibility and actual real-provider log IDs/direct+relay+Sandbox identity must be checked independently. No autonomous release/activation/spending; do not treat synthetic checks as provider acceptance.
