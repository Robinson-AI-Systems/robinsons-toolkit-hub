## Build contract

All plain ES modules, Node 24 built-ins only (`node:http`, global `fetch`) — no new dependencies.

1. `packages/conformance/package.json` — `@robinson-ai-systems/conformance`, private, `"type": "module"`,
   `bin: { "rtc-conformance": "bin/rtc-conformance.js" }`. Root `package.json`: `"test:conformance": "vitest run
   packages/conformance/test"`, and `bin.rtc-conformance` pointing at the same file (so
   `npx github:Robinson-AI-Systems/robinsons-toolkit-hub#conformance-v1` works once K-2b tags it).
2. `packages/conformance/src/run.js` — `runConformance({ url, passes: { full, readOnly?, expired?, revoked? } })` →
   `{ ok, checks: [{ name, ok, skipped?, message }] }`; a check whose pass was not supplied is `skipped` with the reason
   (never silently passed). Check names: K-1's table names if K-1 has merged;
   otherwise the names below (`manifest`, `catalog`, … `budget`, plus `<section>.<rule>` per check), which K-1 adopts.
3. `packages/conformance/src/checks/*.js` (one file per contract section): **manifest** (§1 shape, `rtc: 1`, prefix, `manifest.openapi` bounded definition);
   **catalog** (§3 every name starts with `<prefix>_`, description ≤160 chars, metadata and annotations consistent,
   `MOVES MONEY:` first on money tools); **meta** (§4 search/describe/call/batch ≤10 reads/result/whoami over the HTTPS
   API); **reads** (§7 `fields`, `detail`, >8 KB → handle, list page ≤100 with `next`); **writes** (§6 `dryRun` changes
   nothing, `needs_confirmation` without `confirm`, confirm → read-back `confirmed` + `logged.id`); **passes** (§2
   read-only pass refused on a write, expired → `pass_expired`, revoked → `pass_revoked`); **safety** (no key-shaped
   string in any response; error envelope `{ what, cause, todo, technical, code }` with a §7 code); **budget** (compact
   listing < 5,000 tokens at 4 characters per token).
4. `packages/conformance/fake-server/server.js` — `startFakeServer({ prefix = 'fake', faults = [] })` →
   `{ url, passes: { full, readOnly, expired, revoked }, close() }` on `127.0.0.1:0`. Four in-memory tools: one read
   (with a large result for the handle path), one write, one destructive, one money tool; change log in memory. Passes
   are random per start and never printed. `faults` turn on exactly one violation each: `no-manifest`,
   `write-ignores-dry-run`, `read-only-pass-can-write`, `key-in-result`, `oversize-without-handle`,
   `unprefixed-tool`, `bad-error-envelope`.
5. `packages/conformance/bin/rtc-conformance.js` — `rtc-conformance <url> --pass-env RTC_PASS [--read-only-pass-env …
   --expired-pass-env … --revoked-pass-env …]`; passes come only from environment variables (never argv); prints one
   line per check; exit 0 all ok, 1 any failure, 2 usage error.
6. Docs: AGENTS "How to run things" (`test:conformance` now real), ARCHITECTURE (package built), STATUS, this card,
   `work-index.json`.

## Tests (`packages/conformance/test/`)

- `fake-passes.test.js` — the reference fake passes every check; none skipped when all four passes are given.
- `negative.test.js` — each fault makes exactly its check fail, with a plain message naming the rule (§n).
- `skips.test.js` — omitting the read-only/expired/revoked passes reports those checks `skipped`, never ok.
- `cli.test.js` — exit codes 0/1/2; a pass given on argv is refused; output never contains a pass.
- Secret scan still passes (the fake's passes are generated at run time).
