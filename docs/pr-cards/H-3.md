## First implementation boundary — PR #158

After #157 merged on `d223de4857265cc29b825c43c07ad32708074a23`,
the first H-3 source slice extends H-2's socket-time DNS-pinned, hostname
certificate-verified, no-redirect TLS transport to **GET only**
`/api/tools` and exact `/api/tools/{canonical_name}`. It never uses a
Hub bearer for RTC, accepts only an encrypted separately issued RTC pass
through the H-2 resolver's intended caller, caps bytes/time/metadata, and
filters by exact prefix and caller grant areas. Only metadata advertising
readOnlyHint, no writes/money/destruction and read_only profile can flow out.
On-demand schema fetch is separately bounded; fixed MCP broker menu unchanged.
Two independent simulated RTC HTTPS origins test positive behavior, refusal,
DNS rebinding and no path-based redirect bypass.

This is callable source transport, not yet wired into live Hub broker or owner
dashboard; it cannot execute tools. Exact deployment pin, real upstream TEST
scope/read, hosted DB readiness and two-service Hub acceptance remain OPEN.
